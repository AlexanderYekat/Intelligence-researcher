# Термины

- **Goal** — пользовательская цель уровня проекта.
- **Research Program** — адаптивная программа, которая управляет неизвестными, workstreams и циклами synthesis.
- **Research Question (RQ)** — проверяемый вопрос, ответ на который влияет на решение.
- **Workstream** — направление связанных вопросов и задач; не отдельная вечная сессия агента.
- **Investigation** — ограниченное исследование с evidence и критерием завершения.
- **Spike** — time-boxed практическая проверка feasibility.
- **Finding** — вывод, полученный из evidence и прошедший заданный review.
- **Synthesis** — объединение findings в обновлённую модель задачи и следующий план.
- **Decision / ADR** — выбранное направление с основаниями, альтернативами и условиями пересмотра.
- **Task DAG** — граф задач и зависимостей.
- **Critical path** — цепочка, определяющая минимальный срок достижения цели.
- **Backlog** — полезные, но пока не выбранные задачи.
- **Opportunistic backlog** — неблокирующие задачи, которые выгодно выполнять при свободных ресурсах.
- **Quota pool** — общий ограниченный ресурс, который могут расходовать несколько моделей или интерфейсов.
- **Quota harvesting** — полезное использование скоро сгорающей квоты на высокоценные задачи из opportunistic backlog.
- **Model tier** — абстрактный класс способности модели, не жёсткое имя поставщика.
- **Worker** — конкретный запускаемый исполнитель: CLI, API, MCP, local model или skill.
- **Attempt** — один неизменяемый запуск task определённой версии.
- **Lease** — временное право worker-а выполнять task.
- **Heartbeat** — сигнал, подтверждающий, что attempt жив.
- **Checkpoint** — сохранённое состояние, с которого работу может продолжить новая сессия.
- **Context pack** — минимальный версионированный набор данных для одного worker-а.
- **Artifact** — долговечный результат: документ, evidence, код, лог, dataset, patch или report.
- **Acceptance** — формальное признание результата достаточным; отличается от успешного завершения процесса.
- **Adversarial review** — проверка, специально пытающаяся опровергнуть вывод или найти скрытые допущения.
- **Durable execution** — выполнение, продолжающееся после рестартов и длительных ожиданий.
